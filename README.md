# Журнал бега

Личный журнал километража: Markdown-файлы, PHP CLI без Composer, графики через gnuplot.

## Требования

- PHP 8.2+
- gnuplot 5+ в `PATH` (проверено с 6.0)
- расширение `mbstring`

## Команды

```text
php bin/run log [--date YYYY-MM-DD] <km> [--note "..."]
php bin/run chart [YYYY-MM|YYYY|all]
php bin/run init YYYY-MM [--target <km>]
php bin/run init-year YYYY --target <km>
php bin/run status [YYYY-MM|YYYY]
php bin/run migrate-org
```

`log` сразу пересобирает график месяца и года. `chart` без аргумента обновляет текущий месяц и его год.

## Веб-интерфейс

```text
php -S localhost:8080 -t public
```

Откройте http://localhost:8080 — burn-up текущего года, переход в месяц и ввод тренировки. После сохранения обновляются SVG месяца и года.

## Файлы

```text
2026/year.md    цель года; таблица месяцев генерируется
2026/08.md      тренировки августа
2026/08.svg     burn-up месяца
2026/year.svg   burn-up года
```

Месяц:

```markdown
---
period: 2026-08
target_km: 112
---

# Бег: август 2026

| date       | km  | note |
| ---------- | --- | ---- |
| 2026-08-01 | 4.8 |      |

![График](08.svg)
```

Километраж живёт только в месячных файлах. `target_km` в месяце необязателен: без него график строится только по факту, без пунктира идеального плана. `year.md` хранит `target_km` года; колонка `km` перезаписывается при `chart` / `log`.

## График

Линия факта в **прошедшем** месяце идёт через все дни до конца месяца: после последней тренировки она горизонтальна. В **текущем** месяце линия доходит до сегодняшнего дня. На **годовом** графике линия есть только у закрытых месяцев: август появляется с 1 сентября, сентябрь — с 1 октября. Дни и месяцы впереди — пропуск (`NaN`).

Точка на синей линии ставится только в день (или месяц) с записью в журнале. Дни без тренировки линия проходит, но без маркера.

Если задан `target_km`, идеальный план — прямая от `(0, 0)` до `(конец периода, target_km)`. Её считает gnuplot, не PHP. Без цели этой линии нет, шкала Y берётся по фактическому накоплению.

Несколько тренировок в одну дату суммируются на графике и остаются отдельными строками в журнале. Будущие даты разрешены.

## Миграция с Org

`php bin/run migrate-org` читает старые `*.org`. Месяцы с дневным логом (июль–сентябрь 2026) переносятся как есть. Январь–июнь, у которых были только годовые итоги, получают одну запись на последний день месяца с `note: imported total` и `target_km`, равным этому итогу.
